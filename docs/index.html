Git, without the bloat.

Gitter is a simple, native Git client for macOS. It shows your branches, your commit graph and your diffs, and every action runs through your own git: your SSH agent, credential helpers, hooks and commit signing just work.

Everything you do every day

Gitter covers everyday Git work, from staging single lines to tidying remotes. Nothing is there just to fill a menu.

⎇

History with a lane graph

A gitk-style graph that goes back to the very first commit. Older commits load as you scroll, and clicking an old branch or tag jumps straight to it.

±

Stage files, hunks or lines

Stage a whole file, a single hunk, or just the lines you pick. Commit, amend the last commit, or commit every tracked change in one step.

⑂

Branches and merges

Create, switch, rename, delete and merge, choosing fast-forward, a merge commit or a squash. Check out remote branches, tags and single commits.

⇅

Fetch, pull, push

Run them from the toolbar, with git's own progress line and a Stop button. Ahead/behind counts show on every branch, and a quiet background fetch keeps them current.

⚑

Resolve conflicts in the app

Each conflict appears as blocks, with ours beside theirs and the result shown before anything is written. Then continue, skip or abort the merge, rebase, cherry-pick or revert.

↺

Cherry-pick, revert, rebase

Select several commits and cherry-pick or revert them as one sequence, or rebase onto a commit or a branch. Each action shows a sheet that lists exactly what will run.

⧉

Stash and discard, with undo

Stash everything or only the files you select. Discard a file, a hunk or a single line, and get Undo Discard every time.

⌗

Tags, remotes, worktrees

Create, push and delete tags, with Restore Tag afterwards. Prune remotes, clean up branches whose upstream is gone, and add or remove worktrees.

⌕

Find your way around

Filter the sidebar as you type. Compare two branches to see the commits only on each side and the changes one would bring.

Your work is safe

One promise runs through the whole app:

Gitter never discards uncommitted work or commits without a confirmation that names what will be lost, and a discard also leaves a copy that can be brought back.

Every discard can be undone

A copy of the discarded changes is saved as a stash entry first, and untracked files go to the Trash. Undo Discard brings them back.

Deletes ask git first

A branch is deleted with git branch -d. -D is used only after a warning that names the commits it would lose.

Force pushes are leased

A force push only replaces the exact commit you were shown. If the server has moved on since then, the push is refused.

The plan is checked again

Before a rebase, a prune or a worktree removal, the plan is shown on a sheet. It is checked again just before git runs, and the action is refused if anything changed.

No surprise stashes

When local changes block a switch, a merge or a pull, Gitter offers Stash and Continue. It never stashes by itself, and it hands the stash back with Pop Stash.

A log you can read

Every git call is written to ~/Library/Logs/Gitter/gitter.log, with credentials removed. Nothing leaves your Mac.

01 Install

There are no signed release downloads yet, so you build Gitter yourself. You need Xcode 27, XcodeGen and the Command Line Tools, which provide /usr/bin/git.

git clone https://github.com/Constantine-24/gitter.git
cd gitter
brew install xcodegen
xcodegen generate
open Gitter.xcodeproj      # then press Run

To install Gitter in /Applications instead, build a DMG with bash scripts/package.sh. Add --sign "<your certificate>" to sign it with a self-signed certificate, so macOS keeps its folder permissions across updates. The first time you open it, use Open Anyway in System Settings › Privacy & Security. INSTALL.md covers the certificate, packaging, the first open and updating.

02 Open a repository

Choose File › Open Repository… (⌘O) and pick a folder that contains a Git repository. The window has three parts:

  • The toolbar holds the branch button (the current branch, with its ahead/behind counts) and Fetch, Pull and Push.
  • The sidebar lists your branches, remote branches, tags, stashes and worktrees.
  • The main area shows the commit list with its graph, and the diff of whatever you select.

Everything refreshes by itself when files change on disk, whether you edit in your editor or run git in the terminal.

03 Browse history

  • Click a commit to see its changes. The row at the top of the list is your working copy: the changes you haven't committed yet.
  • Keep scrolling and older commits load 500 at a time. ⌥↓ jumps to the end of what has loaded. The last row says Start of history when you reach the first commit.
  • Click a branch or a tag in the sidebar to select its commit. If that commit is older than what has loaded, Gitter loads down to it and scrolls there.
  • Tags appear as pills on their commit rows. Hover over one to see the tagger, the date and the message.

04 Stage and commit

  • Select the working-copy row to see your changes, unstaged and staged, file by file.
  • Stage a whole file, a single hunk, or select lines in the diff and stage just those. Unstaging works the same way.
  • Write a message in the composer and commit. Turn on Amend to rewrite the last commit. With nothing staged, the button becomes Commit All Tracked.
  • Your hooks and commit signing run as configured, because the commit is made by your own git.

05 Branches

  • Use the branch button or a branch's right-click menu in the sidebar to create, switch, rename, delete or merge.
  • A merge asks each time: fast-forward if possible, always a merge commit, or squash. It remembers your last answer.
  • Check out a remote branch, and Gitter makes a local branch that tracks it. Check out a tag or a commit to look around on a detached HEAD.
  • If your local changes block a switch, choose Stash and Continue and the switch runs again.
  • Choose Compare with on any branch to compare it with the current one and see what each side has that the other doesn't.

06 Fetch, pull and push

  • Fetch ⇧⌘F, Pull ⇧⌘L and Push ⇧⌘P work on the current branch. The one that's running shows git's progress and a Stop button, and ⌘. stops it. You can keep browsing, staging and committing while it runs.
  • A pull fast-forwards when it can. When both sides have new commits, it asks whether to merge or rebase.
  • A branch with no upstream gets Publish. If the server refuses a push because it has commits you don't, you can Pull first, or Force Push… with a lease on the exact commit you were shown.
  • After a push, the hosting service's pull-request link stays on screen with Open and Copy Link.
  • Gitter fetches quietly when a repository opens and every 10 minutes after that. You can turn this off with Repository › Fetch Automatically.

07 Resolve conflicts

  • When a merge, rebase, cherry-pick or revert stops on a conflict, the operation bar says where it stopped, for example "stopped at commit 1 of 3".
  • Select a conflicted file to see each conflict as a block, ours beside theirs. For each block choose Ours, Theirs or Both, and check the result before writing the file.
  • A binary file, a symlink or a deleted file gets a whole-file choice instead. You can also resolve in your own editor and then choose Mark Resolved.
  • Then choose Continue with the stopped commit's message in the composer, Skip This Commit…, or Abort.

08 Cherry-pick, revert, rebase

  • Select one or several commits (⌘-click, ⇧-click), then right-click and choose Cherry-pick or Revert. They run as one git sequence, in the order git needs.
  • Rebase the current branch onto a commit or a branch. The sheet lists the commits it replays and the merges it flattens, and warns you when some of them are already pushed.
  • Before anything runs, Gitter checks the plan again and refuses if it changed after you saw the sheet.

09 Stash and discard

  • Repository › Stash Changes… (⌥⌘S) stashes everything, or only the files you selected, with an optional message and untracked files.
  • The sidebar's Stashes section lists your stashes. Select one to see its files, or right-click it to Apply, Pop or Drop it.
  • Discard a file, a hunk or a single line. The sheet says what goes and where its copy is kept, and Undo Discard brings it back.

A discarded untracked file goes to the Trash, so you can also put it back from Finder.

10 Tags, remotes and worktrees

  • Tags: create an annotated or a lightweight tag on any commit, then push it or delete it. After a delete, Restore Tag puts it back.
  • Remotes: add, rename, re-point or remove a remote. Prune lists every remote branch the server no longer has, and offers to keep a local branch for any commits only they hold. Clean Up Gone Branches… deletes local branches whose upstream is gone.
  • Branches you haven't checked out: push them, fast-forward them, or set and unset their upstream, all from the sidebar.
  • Worktrees: open, add and remove them from the sidebar. Before a removal, Gitter shows what git would delete.
  • Filter: press ⌘F to narrow the sidebar's branches and tags as you type.

11 Windows and quitting

  • File › New Window (⌘N) opens another repository in its own window, with its own sheets and background fetch. A repository is never open in two windows at once.
  • The windows you had open come back at the next launch.
  • Quitting is safe while the network is busy. A fetch or a pull is stopped. A push asks first: Wait, Stop and Quit, or Don't Quit.
  • Help › Show Logs opens the folder that holds the log of every git call Gitter made.
